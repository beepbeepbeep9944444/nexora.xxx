how it works

anyone can write a velocity

knowing the frame to write it on is the whole job. that is where the others fall over.

contact from real movement

checking your speed stops working the second a feature writes its own. wall contact comes from where you actually moved between frames, not from whatever the game was told.

a ground check that holds

one threshold chatters on uneven floors and sets everything off twice. leaving the ground and landing on it use different numbers, so a landing fires once.

the right loop for the job

some of it runs on render, the rest on stepped where velocity writes actually survive the physics step. put them all in one place and half of them break.

faq

before you buy

what do i need to run it?

matcha. it goes straight at matcha's memory and drawing apis, so nothing else will run it. one luau file, paste it in and you are going.

is there aimbot or esp in here?

no. it never touches another player. it moves you and draws your own hud, that is the whole thing.

does it work in every game?

anywhere normal humanoid physics apply. offsets shift when a game updates, so they are sliders you can fix yourself in ten seconds. settings save per place, so each game keeps its own tuning.

can i change the keys?

all of them. right click a bind to flip it between hold, toggle and always. the keys save with everything else.

how do i know it actually fired?

it tells you. the cue names the trick as it happens, the chip lights up for as long as it runs, and you get the numbers after.

what do updates look like?

same single file, newer version. your configs are json sitting on disk and they carry straight over.
